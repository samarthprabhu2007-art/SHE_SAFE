# Instructions for Pull Requests (PRs)

Please follow these workflow guidelines when contributing to the project to keep our Vercel deployment stable and avoid conflicts:

* **Always create a branch** before you start coding. (Do not commit directly to `main`).
* **Claim your issue:** Once you start working on an issue, leave a comment on that issue in GitHub stating that you are working on it.
* **Test locally first:** If you want to test the app, test it using your laptop itself (local environment) before submitting your code.
* **Submitting:** Just submit the PR once your work is done. When you are finished, press the **"Compare & pull request"** button on GitHub to open the PR. Dont Merge the issues ! , even if you have submitted pr , it will be done once we all check the code .
* **⚠️ WARNING - No direct commits to main:** Committing directly on the `main` branch can directly update the live Vercel deployment, which can mess up everything if the code is untested or broken. Always use branches and PRs!
