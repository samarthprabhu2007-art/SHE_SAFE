Part 1: Wireless Camera Radar (How it Works Internally)
1. The Core Concept (The "Why")
Most modern covert spy cameras are wireless. They need to stream video footage to a remote server or phone. To do this, they must transmit radio frequency (RF) signals in the 2.4 GHz spectrum (Wi-Fi) or advertise via Bluetooth Low Energy (BLE) beacons. By scanning these frequency bands, sheSafe can detect their presence, track their signal strength, and guide a user directly to where the camera is hidden.

2. The Multi-Core Architecture (The Hardware Backend)
Explain that you used a dual-core ESP32 microcontroller running FreeRTOS (Real-Time Operating System) to handle two tasks at the same time:

Core 0 (Background Scanning): Runs a dedicated background task (scanTask) that continuously sweeps the Wi-Fi and Bluetooth bands. It collects the names (SSID/Name), unique MAC addresses (BSSID), and signal strengths (RSSI) of all nearby devices.
Core 1 (Web Server): Hosts a local web server (using the Arduino WebServer library) that streams the dashboard HTML/CSS interface and responds to data requests.
TIP

Why this matters to judges: If you ran scanning and the web server on the same core, the web server would freeze for 3–5 seconds during every scan. Using dual cores keeps the dashboard loading instantly with 0ms latency while scanning runs in the background. We used a Mutex Semaphore (jsonMutex) to safely share the scanned data between the two cores without memory corruption.

3. The REST API (Telemetry Exchange)
When your mobile phone connects to the ESP32, it receives the frontend dashboard. The browser then starts polling the ESP32 in the background using REST API endpoints:

/wifi: Returns a JSON list of all detected Wi-Fi networks.
/ble: Returns a JSON list of all detected BLE devices.
4. The Guidance Engine & Gradient Ascent (The Math & Physics)
Once a user clicks "LOCK" on a target device (like SPY_CAM_WIFI), sheSafe initiates the directional compass guidance:

Sector Mapping: The compass divides the physical 360-degree space around you into 8 sectors of 45° each (North, North-East, East, etc.).
Sensor Fusion: The frontend requests access to your phone’s internal motion sensors (deviceorientation API) to track the phone's yaw/compass heading in real time.
Gradient Ascent (Signal Tracking):
As you walk in different directions, the phone's browser logs the signal strength (RSSI, measured in dBm) in the active sector.
If the RSSI gets stronger (e.g., goes from -75 dBm closer to -50 dBm), the algorithm recognizes a positive gradient (+dBm) and knows you are getting closer. It guides you to "PROCEED FORWARD".
If the signal drops, it suggests you "TURN AROUND" or steer left/right to find the path of ascending signal strength.
Proximity Alert: Once the signal crosses -50 dBm (the proximity threshold), the system declares the target "FOUND" (meaning you are within 1–2 meters of it).
5. Spatial Memory & Obstacle Avoidance (The "HIT WALL" Feature)
If you walk towards a signal but hit a physical barrier (like a concrete wall or furniture), you press "HIT WALL":

The system blacklists that specific 45° sector.
It looks at its spatial memory (the average RSSI recorded in neighboring sectors) and suggests a path around the obstacle (e.g., "MEMORY SUGGESTS: TURN LEFT" or "TURN RIGHT") so you can navigate around the wall to reach the camera.






🎯 How Judges Will Ask Questions (And How to Answer Them)
Q1: "Wi-Fi and BLE antennas on phones and ESP32 are omnidirectional (they receive signals from all directions). How can the compass guide you in a specific direction if the phone receives the signal equally from all sides?"
Your Answer: "That is a key feature of our software design. Because standard antennas are omnidirectional, we cannot know the direction from a single static measurement. Instead, we use spatial memory (differential tracking). As the user walks and rotates, the phone's gyroscope maps RSSI values to specific physical directions (sectors). By comparing the current signal to the previous sector's average, the software calculates the directional gradient (whether the signal is increasing or decreasing). We are not relying on a directional antenna; we are relying on user movement and sensor fusion to map the RF environment."
Q2: "How does sheSafe distinguish a regular home Wi-Fi router from a spy camera?"
Your Answer: "sheSafe is built to identify candidates. It flags networks that match common manufacturer signatures of covert devices (such as IP cameras) or specific signal behaviors. Additionally, the dashboard allows the user to filter signals by strength (RSSI threshold) so they can isolate high-strength, nearby signals (which are likely hidden in the same room) and ignore distant routers outside the room."
Q3: "What is RSSI and why is it measured in negative numbers?"
Your Answer: "RSSI stands for Received Signal Strength Indicator. It is measured in decibels relative to one milliwatt (dBm). Because radio waves decay over distance, the received power is a tiny fraction of a milliwatt. In logarithmic scale, a fraction of a milliwatt is represented as a negative number. A value of -30 dBm indicates an extremely strong, close signal, while -90 dBm indicates a very weak, distant signal."
Q4: "How does the compass simulate rotation on the phone during your demo?"
Your Answer: "During demonstration or testing, we built a client-side orientation simulator. When a target like SPY_CAM_WIFI is locked, the JavaScript tracks the phone's gyroscope. It simulates a physical beacon located at 90° East. If you point the phone toward 90° East, the RSSI rises to -45 dBm (target locked). If you rotate away, the simulated signal drops to -85 dBm. This lets us prove the vector steering logic works perfectly without requiring an active physical transmitter."






Part 2: Wired Camera Detector (How it Works Internally)
1. The Core Concept (The "Why")
Some spy cameras do not transmit wireless signals (no Wi-Fi or BLE). Instead, they are wired directly to a local recording device or save footage onto an internal SD card. To detect these "silent" cameras, sheSafe uses optical computer vision (CV):

Near-Infrared (IR) Illumination: Covert cameras use built-in IR LEDs to record in low-light conditions. While this light is invisible to the human eye, digital camera sensors (like your phone's camera) can capture it. It typically appears on screen as a bright, glowing pink, purple, or white-pink dot.
Rhythmic Blinking: Many hidden cameras flash their IR lights at a specific frequency to sync with their frame rate or save power. sheSafe detects this exact blinking rhythm to identify the camera.
2. The Step-by-Step Technical Flow
Step A: Video Stream & Downsampling (Real-time Capture)
The frontend requests access to the phone's camera using the HTML5 WebRTC API (getUserMedia).
Each video frame is drawn onto a hidden canvas element downsampled to 320x240 pixels.
NOTE

Why we downsample: Processing a full-resolution 1080p video frame in JavaScript on a phone would lag severely. Downsampling to 320x240 reduces the number of pixels to process by 90%, allowing the CV algorithm to run at a smooth, real-time 30+ FPS directly inside a mobile web browser.

Step B: Color Filtering (The HSL Color Space)
The algorithm inspects the color of each pixel in the 320x240 grid:

It converts the pixel's RGB (Red, Green, Blue) values to HSL (Hue, Saturation, Lightness). HSL is much better than RGB for color detection because it separates color (Hue) from brightness (Lightness).
It filters for the Infrared optical signature:
It checks if Red and Blue are high while Green is low (which forms the pink/magenta glow: r > 50 && b > 50 && r > g + 2 && b > g + 2).
It checks if the Hue is close to the target center (default is 315°/300° representing magenta/pink) within a tolerance (default ±30°).
It ensures minimum saturation and lightness thresholds are met.
Step C: Blob Clustering (Finding Targets)
Once the matching pixels are identified, the algorithm clusters them into distinct targets ("Blobs") using a queue-based Breadth-First Search (BFS) clustering algorithm:

It groups adjacent matching pixels together.
It filters out noise: a real spy camera lens reflection is very small and concentrated. The code rejects clusters that are too large (e.g., greater than 250 pixels) or wider than 50x50 pixels.
Step D: Temporal Frequency Analysis (Blink Detection)
This is the most critical part. To prevent false alarms (like a user wearing a pink shirt, or a static pink light in the room), sheSafe tracks the brightness of each target over a rolling 5.5-second history:

Transition Tracking: The algorithm establishes a threshold (average brightness of the blob) and counts when the blob crosses it (goes ON and OFF).
Frequency Matching: It measures the duration of each blink. If the blinking rate matches the target setting (default 500ms / 1.0 Hz) with low jitter (variation), the Threat Score climbs.
Alarm Trigger: If the threat score reaches 75%, it locks a red tracking reticle on the screen, sounds the critical alarm, and triggers the automated WhatsApp alert!




🎯 How Judges Will Ask Questions (And How to Answer Them)
Q1: "Don't modern smartphones have IR cut-filters on their cameras that block infrared light?"
Your Answer: "Most main rear-facing cameras do have IR cut-filters to improve normal color photos. However, front-facing (selfie) cameras and cheaper webcams usually do not have strong IR filters, or lack them entirely, allowing them to see near-infrared light clearly. Additionally, near-infrared light (around 850nm - 940nm) emitted by spy cameras is strong enough to leak through many standard smartphone filters, showing up as a distinct purple-pink light."
Q2: "How does the algorithm prevent false positives, like someone waving a pink toy or walking past a pink wall?"
Your Answer: *"We use two layers of protection: spatial filtering and temporal filtering.
Spatial: We only accept small, concentrated, high-density circles (blobs) matching a lens signature. Large pink objects (like shirts or walls) are ignored.
Temporal: This is our main defense. The system tracks the target's behavior over time. A static pink light or a randomly moving object will have a chaotic signature. The alarm is only triggered if the target blinks at a highly consistent, rhythmic frequency (e.g., exactly 500ms ON / 500ms OFF) with minimal timing variation (low jitter)."*
Q3: "Why did you build this in JavaScript in the browser rather than on a Python server?"
Your Answer: "By running the computer vision engine in the browser (client-side), all video processing happens locally on the user's phone. We do not stream video data over the network, which ensures absolute user privacy and reduces network bandwidth to zero. It also allows the system to work instantly without needing to send heavy video frames to a backend server."
Q4: "How does the 'Simulate Spy Cam' button work?"
Your Answer: "For demonstration purposes, if a physical blinking IR LED isn't available, clicking the simulate button draws a virtual pink dot on the canvas that orbits in a circle and blinks at exactly 500ms. This lets us verify that the tracking bounding boxes, frequency algorithms, threat scoring, and WhatsApp API endpoints trigger exactly as designed under real-world conditions."





Part 3: IoT Alert & Networking System (How it Works Internally)
1. The Core Concept (The "Why")
Physical camera detection is only half the battle. To provide a complete personal security solution, sheSafe needs an automated alert system:

Passive Intruder Monitoring (PIR): Monitors the environment for physical movement in the room (e.g. if an intruder enters the space while you are asleep).
Emergency Dispatch (SOS): Allows the user to manually trigger a panic alert. If they feel unsafe, they can click a button to send their exact location and time to a trusted contact.
Stand-alone Portability: Bypasses traditional networking limitations so the system can be deployed anywhere (e.g., in a hotel room, Airbnb, or changing room) using just the ESP32 and a phone.
2. The Step-by-Step Technical Flow
Step A: PIR Motion Sensor Polling
The ESP32 reads state updates from a Passive Infrared (PIR) motion sensor connected to its hardware pins.
The dashboard browser continuously polls the ESP32 at /pir-status every 2 seconds.
If motion is detected, the dashboard changes the status card to MOTION DETECTED in bright red, sound alerts, and logs the activity. (For demonstration purposes, we mock this state: active for 4 seconds, clear for 11 seconds).
Step B: The Geolocation SOS Panic Button
When the user taps the 🚨 SOS EMERGENCY button in the header, the browser requests the phone's GPS data using the HTML5 Geolocation API.
If allowed, it retrieves the phone's exact latitude and longitude.
It constructs a warning message: 🚨 EMERGENCY SOS ALERT: I need assistance immediately! Time: [timestamp], Location: https://maps.google.com/?q=[lat],[lon]
If GPS is turned off or blocked, the safety fallback triggers, sending the message immediately with the label Location: Location Unavailable so that the alert is never delayed.
Step C: Green API Integration (WhatsApp Gateway)
The phone browser initiates an HTTPS POST request directly to the Green API gateway using the friend's instance credentials: https://7107.api.greenapi.com/waInstance7107650314/sendMessage/48984660ecf34156bed84404ba9a9ebeeed2dec466144fd4bd
The request payload defines the destination chatId (918317470775@c.us) and the message content.
Green API routes this request to WhatsApp's global servers, delivering it to the recipient's phone as a standard WhatsApp message.




🎯 How Judges Will Ask Questions (And How to Answer Them)
Q1: "What is a PIR sensor and how does it work?"
Your Answer: "PIR stands for Passive Infrared. Every object (including humans) emits heat in the form of infrared radiation. The PIR sensor has two slots made of a special material sensitive to IR. When a person walks past, the sensor detects the temperature differential between the two slots. It is called 'passive' because it doesn't emit any energy itself; it only measures the IR radiation emitted by objects in its field of view."
Q2: "Why did you use Green API instead of WhatsApp's official Business API?"
Your Answer: "WhatsApp's official Business API has strict template verification rules, costs money per message, and requires a registered business profile. Green API allows us to link a standard personal WhatsApp account via a developer sandbox. This is perfect for personal safety applications because it lets a normal user send custom, real-time emergency messages from their own personal phone number instantly and for free."
Q3: "How does the HTML5 Geolocation API work? Does it work indoors?"
Your Answer: "The HTML5 Geolocation API is built into modern web browsers. It uses a combination of GPS (Global Positioning System) satellites, cellular tower triangulation, and nearby Wi-Fi network databases to determine the phone's coordinates. Outdoors, it uses high-accuracy satellite data. Indoors, it falls back to cellular and Wi-Fi positioning, which is fast and works inside buildings."
Q4: "Why did you connect the ESP32 to the mobile hotspot instead of just connecting it to a home Wi-Fi router?"
Your Answer: "Connecting the ESP32 to the phone's mobile hotspot makes the entire system completely portable. If the user travels to a hotel, an Airbnb, or is in a public place with no home Wi-Fi, they can simply power on the ESP32, turn on their phone hotspot, and sheSafe is fully online and operational immediately."
