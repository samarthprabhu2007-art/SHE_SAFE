WHAT THE SYSTEM DOES
This device detects hidden/spy cameras in a room using only an ESP32 microcontroller and the user's smartphone (no app install, no cloud, no home Wi-Fi dependency). It has two detection subsystems plus an emergency alert feature, all served from one ESP32-hosted web dashboard:

1. WIRELESS CAMERA RADAR — detects spy cameras that transmit over Wi-Fi or BLE, and guides the user toward the source using directional signal-strength tracking.
2. WIRED CAMERA DETECTOR — detects offline/SD-card spy cameras using the phone's camera and real-time in-browser computer vision to catch the IR LED glow + blink pattern these cameras emit.
3. EMERGENCY SOS — a GPS-based panic button that sends WhatsApp alerts to a trusted contact.

CURRENT TECH STACK (already built, working)
- Firmware: ESP32 in Arduino/C++, using WiFi.h, WebServer.h, NimBLEDevice.h.
- Concurrency: FreeRTOS dual-core split — Core 0 runs a background scanTask (Wi-Fi + BLE scanning), Core 1 runs the WebServer loop. A mutex semaphore (jsonMutex) protects shared JSON strings (wifiJson, bleJson) between cores.
- REST endpoints exposed by the ESP32: GET /wifi, GET /ble, GET /pir-status, GET /trigger-whatsapp (and / serving the dashboard HTML).
- Dashboard: a single embedded HTML/CSS/JS page (stored via PROGMEM, chunk-streamed to the browser) with two switchable modes (Wireless Radar / Wired Detector), canvas-based radar and signal-plot visualizations, and a shared console log.
- Directional guidance (wireless mode): 8 compass sectors (45° each), gyroscope/compass heading via the browser's deviceorientation API, gradient-ascent logic comparing RSSI trends per sector to guess the best direction, a "HIT WALL" feature that blacklists a sector and suggests routing around it using neighboring sector data. FOUND state triggers at RSSI ≥ -50 dBm.
- CV pipeline (wired mode): getUserMedia camera capture → downsample to 320×240 → RGB-to-HSL pixel filtering for magenta/pink IR signature → BFS blob clustering (rejects blobs >250px or >50×50 bounding box) → rolling 5.5s brightness history per blob → blink-transition consistency check (rate + jitter) → threat score 0–100 → alarm + WhatsApp trigger at threat score ≥75.
- Alerts: sent directly from the browser via a client-side fetch() POST to a Green API WhatsApp gateway endpoint (not sent through the ESP32 itself — the ESP32's own /trigger-whatsapp handler is currently just a Serial-log simulation, not a live send).
- SOS button: HTML5 Geolocation API fetches GPS coordinates; if denied/unavailable, the alert is still sent immediately labeled "Location Unavailable" rather than delayed.
- Networking: ESP32 runs its own Access Point (WiFi.softAP) for the dashboard, and also joins a phone's mobile hotspot in the background for internet-dependent features (Green API calls, made from the browser).
